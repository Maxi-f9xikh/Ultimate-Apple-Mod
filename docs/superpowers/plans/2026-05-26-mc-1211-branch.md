# MC 1.21.1 Branch (NeoForge) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a `1.21.1` Git branch from `main` with the `forge/` subproject ported to NeoForge 21.1.172, Java upgraded to 21, and all Minecraft 1.21.1 API breaks fixed (FoodProperties lambda→instance, package renames net.minecraftforge→net.neoforged, constructor injection).

**Architecture:** The `forge/` folder keeps its name but is rewired to NeoForge. `mods.toml` is renamed to `neoforge.mods.toml`. All `net.minecraftforge.*` imports become `net.neoforged.*` equivalents. `FoodProperties.Builder` method names changed in 1.21.1 (alwaysEat→alwaysEdible, saturationMod→saturationModifier, lambda effects→direct instances). The constructor of the mod main class changes from `FMLJavaModLoadingContext.get().getModEventBus()` to injected `IEventBus` parameter.

**Tech Stack:** Architectury Loom 1.10-SNAPSHOT, NeoForge 21.1.172, Fabric Loader 0.16.13, Fabric API 0.107.3+1.21.1, Architectury API 13.0.8, Java 21, Gradle 8.

```java
    public ultimate_apple_modForge(IEventBus modEventBus) {
```

## Task 7: Fix FoodProperties API in ultimate_apple_modForge.java

**Files:**
- Modify: `forge/src/main/java/de/maxi/ultimate_apple_mod/forge/ultimate_apple_modForge.java`

In Minecraft 1.21.1, three `FoodProperties.Builder` method signatures changed:

| Old (1.20.x) | New (1.21.x) |
|--------------|--------------|
| `.alwaysEat()` | `.alwaysEdible()` |
| `.saturationMod(float)` | `.saturationModifier(float)` |
| `.effect(() -> new MobEffectInstance(...), float)` | `.effect(new MobEffectInstance(...), float)` |

The lambda wrapper `() ->` must be removed from every `.effect(...)` call. The other two are simple renames.

- [ ] **Step 1: Replace .alwaysEat() with .alwaysEdible()**

In IntelliJ: Edit → Find → Replace in Files, scope = `ultimate_apple_modForge.java`
- Search: `.alwaysEat()`
- Replace: `.alwaysEdible()`

- [ ] **Step 2: Replace .saturationMod( with .saturationModifier(**

- Search: `.saturationMod(`
- Replace: `.saturationModifier(`

- [ ] **Step 3: Replace lambda effects with direct instances**

- Search (regex): `\.effect\(\(\) -> (new MobEffectInstance\([^)]+(?:\([^)]*\))*[^)]*\)), ([\d.]+f)\)`
- Replace (regex): `.effect($1, $2)`

If the regex doesn't capture multi-line effects cleanly, do it manually using the following pattern.

**Example — before:**
```java
.effect(() -> new MobEffectInstance(MobEffects.REGENERATION, 20 * 5, 0), 1.0f)
```
**Example — after:**
```java
.effect(new MobEffectInstance(MobEffects.REGENERATION, 20 * 5, 0), 1.0f)
```

For effects referencing registry objects (e.g. `CURSE_OF_ROTTEN.get()`):

**Before:**
```java
.effect(() -> new MobEffectInstance(CURSE_OF_ROTTEN.get(), 400, 0, false, true), 1.0f)
```
**After:**
```java
.effect(new MobEffectInstance(CURSE_OF_ROTTEN.get(), 400, 0, false, true), 1.0f)
```

Apply this to all ~100 effect calls in the file. The pattern is uniform: remove `() -> ` before every `new MobEffectInstance`.

```bash
git add forge/src/main/java/de/maxi/ultimate_apple_mod/forge/ultimate_apple_modForge.java
git commit -m "Fix FoodProperties API for MC 1.21.1 (alwaysEdible, saturationModifier, direct effects)"
```
